# 1. Describe differences between REST API, MCP in the context of AI.
REST API and MCP in the context of AI are used to gather external data and updated information for context enrichment. Rest API is the more general way to integrate one app to another and MCP is made specifically for LLM to be able to interact with tools. The main difference is how they triggered. REST API designed to run according to the human hardcoded code, meanwhile MCP can run by the decision of the LLM. In order to call an API, the code has to know when it will be triggered and it is very clunky to be used for an AI system. I got a project on early 2024 where I had to create an agent to categorize the user intent from a pre-defined list and running it through if-else router to activate what tool it can access. It was unpractical because many things will need to be fixed when a new tool get introduced. With MCP, a new tool introduction wont break the client. Another important difference is that MCP is globally standardized. Not like REST API that having different structure on various enviroments.

# 2. How REST API, MCP, can improve the AI use case.
REST API and MCP can give AI the ability to access a real-time data and various tools. It will lower the chance of hallucination because the needed data is provided and it wont rely on its own knowledge. MCP also helps world known tools like Github, Figma, n8n, and etc to integrate with AI. After MCP introduced, AI direct use case on everyday tools is enabled and it keeps growing rapidly.

# 3. How do you ensure that your AI agent answers correctly?
AI can answer wrongly because of either it hallucinates, the retrieved information is wrong, or the source itself already contains incorrect information. Evals need to be done before deployment to ensure the AI is sane. A question-answer pair dataset is used for evals and an eval threshold need to be passed in order to deploy one. If an AI hallucinates, a guardrail need to be created so that it must prioritize given context over its own memory. Specifically for an internal AI, RAG can also be implemented and The temperature can also be lowered. If RAG exists on the system, the top-n retrieved chunks must be verified because those are what passed to the AI. The last thing is source verification, that is why metadata is important. If the information from the source is wrong, data reconcilliation need to be done.

# 4. Describe what can you do with Docker / Containerize environment in the context of AI
Docker is very important for AI system deployment to control resource usage and installed dependencies. A complex AI system can easily broken with incorrect dependency, so this functionality is important. AI system and all of its components are usually eats an unpredictable amount of resource. If there is no limiter applied, it can affect the runtime of the system itself.

# 5. How do you finetune the LLM model from raw ?
Since I never train an LLM from the foundation level, I will assume that not all the weights are retrained here. If what this question asks is a full weight finetune, I will try to answer it on the next interview.

To train an LLM, after picking a model, a dataset of question-answer pair structured with the model's dataset format need to be prepared. The training process done using LoRA technique to train a low-rank layer under the model's original weight, so that it does not eats so many resource. Same as a DL model training, train/val dataset split, loss monitoring, and hyperparameter tuning need to be done here. After the training is done, an evals need to be done to verify how the model perform.
